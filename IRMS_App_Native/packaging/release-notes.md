IRMS v1.3.0-beta.15 is the fifteenth Windows x64 installer for the Rust/Slint native application.

Download `IRMS_1.3.0-beta.15_x64-setup.exe`. This current-user installer adds desktop and Start menu shortcuts and an uninstaller. Installed by hand it runs alongside the Tauri application; installed by the updater it replaces it. No WebView2 installation is required.

The app starts in real device (Bluetooth) mode; an **IRMS Simulator Demo** Start menu entry (`--simulate`) starts the simulator. Calibration accuracy and feedback acceptance on a worn device remain incomplete; this release does not yet have feature parity with Tauri. Simulated readings are not real measurements.

**New since beta.14** (found and checked on a real device on a desk, nobody wearing it): (1) A lost Bluetooth link is now noticed (about 10 s) and the app reconnects by itself; before, it kept showing 裝置已連線 forever after the device lost power or restarted. (2) Exported CSV files open in zh-TW Excel with readable Chinese. (3) Long connection advice is no longer cut off at the window edge. (4) Firmware update: a completed update is no longer reported as failed (the app reads the restarted device's version); aborting during the download no longer flashes; disconnect, window close and a manual app install are refused while an update transfers. A full update and an abort were run on a device.

**New in beta.14 (since beta.13):** (1) Modules can now be updated on their own, without a new app release. Settings → 模組 lists the signed content packs from the IRMS-Modules index, with install, update, roll back to the previous version and reset to the built-in content. Every pack is checked against the signed index (Ed25519) when it is downloaded and again each time it is loaded; older or replayed versions are refused. The first pack is the session usage tips (session-tips 1.0.0, needs this version); the built-in tips stay as the fallback. (2) The app checks for module packs by itself shortly after launch and every six hours, downloads in the background and installs only when no session, wizard or dialog is open; this can be turned off in Settings → 模組. A version you rolled back from stays listed and marked and is never installed automatically; a newer version resumes automatic updates. Module downloads have not been checked on the owner's laptop yet. (3) Installer: after closing a running IRMS it now waits for the program file to be released before replacing it (an automatic update could stop on a "Close IRMS Native Beta before installing" box).

**New in beta.13 (since beta.12):** (1) 角度範圍測量 now follows the original module: record comfort, then limit or skip, then review the values with a note; one record per measurement (before, recording the limit stored a second record), a dated history of the newest six with trend and 目前生效, and a confirmed delete of one record (before, 清除 removed every record). (2) Usage tips are listed under 設定 → 模組. (3) Strap slip correction: when the shin sensor turns on the leg during knee repetitions spanning at least 60°, the app moves the calibrated axis to where the movement shows it now is, says "已自動修正" and stores the corrected calibration when the session ends; a quick re-zero afterwards removes any remaining offset. Simulator-checked only. (4) The 3D 姿態 view now uses the forward and sideways tilt of both segments (hip abduction moves the knee outward on either leg). (5) Settings texts corrected (firmware install, telemetry choice is remembered).

**New in beta.12 (since beta.11):** (1) The app now reconnects by itself after an unexpected link loss (3 rounds, 3 s apart, each round already retries inside); "取消連線" or any manual connect/disconnect stops it. (2) Every Bluetooth call that holds the shared lock (scan, command write, firmware-version read, OTA abort) now has a time limit, so one stuck Windows call can no longer freeze the other Bluetooth actions. (3) Security: the bundled SQLite is updated (rusqlite 0.43, fixes RUSTSEC-2026-0459). (4) Self-update fixes: a failed installer start no longer retries every tick, the downloaded installer is verified again right before it starts, and no automatic update happens while a live share is being hosted. (5) The uninstaller closes a running app by itself. (6) "找不到裝置" and "NotConnected" errors now say what to check (Windows may be holding a paired IRMS_Device: remove it in Windows Bluetooth settings). (7) The firmware install buttons are hidden while an update runs; a missing calibration reference is reported instead of crashing the wizard.

**New in beta.11 (since beta.10):** the window no longer stays on "連線中" forever. Owner report: Windows showed IRMS_Device as connected but the app kept saying connecting; telemetry of that run had no result at all (no success, no error), so a Windows Bluetooth step was waiting without end. Connect (20 s), service discovery (20 s), subscribe (10 s) and the cleanup disconnect (8 s) now have time limits; a timeout becomes an error that names the step and is retried like any failed connect (3 tries, fresh scan). While connecting, the button now reads "取消連線" and cancels the attempt. "Not connected" and timeout errors now say what to check (power, distance, replug the device, remove the old IRMS_Device pairing in Windows Bluetooth settings).

**New in beta.10 (since beta.9):** (1) Connecting to the device now retries up to three times with a fresh scan when the connection fails after the device was found (Windows can return a cached advertisement for a device that is not connectable yet: telemetry showed "Not connected [NotConnected]" after a restart). A device that is not found at all, and a disconnect pressed during the wait, still stop at once. (2) Firmware update (OTA) is now available in Settings > Software and firmware: "檢查韌體", then, when the connected device runs an older firmware, "更新韌體" with a confirm step, a progress bar and an abort button. The image is checked against the signed manifest (size, SHA-256, MD5) before sending; no session can start during an update. The transfer through the Windows Bluetooth stack has NOT been validated on a physical device yet (an OTA attempted from the Tauri app on 2026-09-26 never reported completion); the firmware switches only after a complete checked image, so a failed or aborted transfer leaves the device on its current firmware.

**New in beta.9 (since beta.8):** automatic updates (Settings > Software): the app checks the beta channel shortly after launch and every six hours, downloads the signed installer, verifies its signature against the built-in key and, when no session, wizard or dialog is open, installs it silently (the app closes by itself, then reopens). It can be turned off there; "檢查更新" and "立即安裝" work by hand. The installer now closes a running IRMS by itself before replacing files. The wearing check can start without re-zeroing, and a failed re-zero now says why instead of closing the dialog. A window restored from minimized is repainted completely (it came back partly black). The owner confirmed on a real device: connection, calibration and a session work; the wizard posture fix works. CSV export, renderer choice and IME are still unconfirmed.

**New in beta.8 (since beta.7):** the calibration wizard now shows all five starting postures (standing, long sitting, supine, seated, other) as buttons you can pick directly; before, one button cycled through them and showed only one at a time. The first real-device run (beta.7) connected and streamed live angles; calibration, session and CSV on the real device are still not confirmed.

**New in beta.7 (since beta.6):** the app now starts in real device (Bluetooth) mode. In beta.1 to beta.6 the normal shortcuts ran the simulator and the connect button only started demo data; the real device path needed `--real-ble`. The simulator is now `--simulate` (Start menu: IRMS Simulator Demo); the window footer shows "裝置資料" or "模擬資料 · 不是真實量測". The opt-in telemetry choice is now remembered between launches (still off by default), and two calibrations created in the same millisecond no longer share an id. Real device connection has not yet been confirmed on hardware.

**New in beta.6 (since beta.5):** the Tauri beta updater now offers this build. Updating removes the Tauri app (its data folder is left alone) and installs this one, which opens itself afterwards. On the first launch it copies the Tauri records (sessions, readings, prescriptions, personal ranges, mobility records, calibrations) into its own database; the Tauri database is read through a copy and never modified. Import runs once, only into an empty native database. Not carried over: settings the Tauri app kept in its WebView (alarm limits, display choices); re-enter them. This is a beta channel build; physical-device acceptance is still pending.

**New in beta.5 (since beta.4):** firmware check in Settings (fetches the channel manifest, verifies its Ed25519 signature with the built-in key and compares it with the connected device). There is no install button: OTA through the Windows BLE backend is not validated on a physical device, use the Tauri app to update firmware.

**New in beta.4 (since beta.3):** opt-in telemetry upload (Settings / Data and privacy; off at every launch, nothing leaves the computer until it is turned on, no name or computer name is sent) and live share (Tools): share this device's live numbers with a code, or watch another device. Remote setting changes from a viewer are refused.

**New in beta.3 (since beta.2):** session CSV export from History (system save dialog, same metadata header and full readings as the Tauri export) and single-instance launch (a second start shows the running window). Modules are built into the program (design decision D2).

**New in beta.2 (since beta.1):** ordered BLE session feedback, alarm mute and Windows speech; editable prescriptions with persistent preferences; a calibration wizard with leg choice, calibrate / mobility / quick re-zero presets, whose calibration is restored at startup; range-of-motion records with a comparable trend; and a wearing check before a session on a real device (an offset small enough to be the strap can be re-zeroed on the spot).

Session storage includes interrupted-session recovery and retry of failed final writes. A force kill or power loss can still lose readings retained only in memory. Uninstall preserves native records in `%LOCALAPPDATA%\irms-native-prototype\irms.sqlite`.

**Windows security:** the installer and application are unsigned. Smart App Control may still block this release. An installer or a self-signed certificate does not resolve public trust. Public signing is pending a trusted signing service or CA-issued certificate. This release does not modify Windows security settings. [Microsoft signing guidance](https://learn.microsoft.com/windows/apps/develop/smart-app-control/code-signing-for-smart-app-control).

This is a beta-channel build: Tauri beta installations are offered it as an update.

Slint attribution is available through the application's About button. IRMS and third-party license notices are included in the installation folder.

Validation on the build machine: native and core regression tests, Clippy with warnings denied, and an installed-release smoke test were run. The wizard, mobility and wearing logic were exercised on a simulated two-sensor rig only; none of it has been accepted on a physical device. These checks do not establish Smart App Control compatibility.
