# 生物回饋、狀態機與動作學習

回饋鏈有三個獨立問題：量測是否可信、使用者是否理解，以及介入後是否改變功能。LED 亮起或蜂鳴器響起只是系統輸出，不代表使用者完成安全且有效的動作。量測與回饋原型的接受度研究，以及部分疾病的介入試驗，應分別使用。[骨科原型評估](../sources/PMID-30669657.md)、[神經疾病回饋回顧](../sources/PMID-34063355.md)

IRMS 的 `TriggerEngine` 使用目標區、維持時間與返回休息等狀態。研究時應把每一次計次的定義寫清楚：必須進入哪一區、多久、是否允許短暫離開，以及下一下是否必須回到休息位。舒適／極限提示與達標計次的觸發條件也應分開測試。

| 測試情境 | 需要觀察的結果 |
|---|---|
| 在目標邊界抖動 | 是否反覆提示或誤計 |
| 進區後資料中斷 | 是否把缺失時間當作維持 |
| 已完成但未返回休息 | 是否重複累計 |
| 回饋指令送出後斷線 | 硬體是否停在錯誤狀態 |
| 量測跳變或錯誤封包 | 是否產生不合理成功或警報 |
| 使用者看不到／聽不到提示 | 是否仍能理解狀態 |

遲滯、去抖與維持時間是工程策略；臨床合理的目標與提示頻率需要專業人員及目標族群確認。回饋可指向「結果」或「如何完成」，也可以連續或摘要呈現。比較時須固定運動劑量與其他教學條件，否則無法分離回饋形式的影響。

即時改善與動作學習不同。應設計回饋撤除、保留與情境轉移測試：訓練當下較接近目標，是否在沒有提示時仍能做到？是否只是盯著畫面才改變？膝骨關節炎步態學習及截肢回饋文獻提供這些問題的背景，但不直接證明 IRMS 有同樣結果。[學習與認知需求](../sources/PMID-29494998.md)、[保留與使用性](../sources/PMID-32183338.md)

紀錄應同時保存進區、達標、返回休息、超限、靜音、指令、裝置回應與缺失資料事件。端到端延遲要從參考動作發生到使用者實際接收到提示測量，不能只測 App 函數執行時間。
