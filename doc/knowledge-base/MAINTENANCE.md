# 維護與擴充

新增來源以可追溯、去重及可解釋的相關性為準。不要為增加數量收錄沒有 IRMS 用途或無法辨認身分的來源。

## 更新流程

1. 定義問題、截止日與查詢。可用 `scripts/collect_candidates.py --output <暫存目錄> --cutoff YYYY-MM-DD`；加 `--sort-cited` 可找經典文獻。引用次數不代表品質。候選檔存暫存目錄，不直接進正式資料庫。
2. 核對標題、作者、DOI、PMID、首次出版日與版本。檢查更正／撤稿狀態與是否已有同一來源；本次排除條件不保證找出全部後續通知。
3. 讀摘要或原文並據實標記閱讀深度。寫原創整理、IRMS 用途、適用限制與證據定位。方法研究、研究計畫、資料集與臨床結果分開辨認。
4. 編輯 `data/catalog.json`；必要時更新 topics、導讀、引用主張及驗證計畫。新記錄保持既有欄位，新增主題需有可用來源。
5. 官方來源用 `scripts/verify_links.py --output <暫存 JSON>` 查核。查看實際內容；HTTP 200 或 PDF 檔頭不能代替閱讀。失敗時保存狀態與官方目錄入口。
6. 執行 build.py 與 check.py；核對卡片、引用匯出及搜尋。更換截止日後，同步更新 README 的人工說明與查詢紀錄。
7. 在 repo 的 `doc/coding log/` 新增英文變更紀錄並更新 `doc/HOME.md`；依專案工作流程 commit、push 與 PR。

```powershell
python doc/knowledge-base/scripts/build.py
python doc/knowledge-base/scripts/check.py
node doc/knowledge-base/scripts/check_search.js
python doc/knowledge-base/scripts/query.py "校準" --core
```

## 升級閱讀深度

從摘要升級到全文章節時，補上頁碼／章節及檢查日期，再更新整理。若要支持正式性能或臨床主張，需提取研究族群、樣本數、硬體、任務、參考系統、同步、誤差及不確定性；加入適當的偏誤風險評估。只讀結論不能標記為完整系統性審查。

對現有版本來源，保留原 ID 與追溯；對獨立的新版本／新版指南，建立新 ID 並寫出替代關係。若來源撤稿，保留其歷史記錄、撤稿通知與禁用理由，從有效主張及優先閱讀中移除，不靜默抹去已引用紀錄。

## 維護優先順序

- 優先完整提取核心校準與量測驗證文獻。
- 每次 IRMS 演算法／協定／資料格式改變時，更新程式對照與原始資料可重現性限制。
- 正式報告提交前，重新檢查該報告實際引用的版本、原文與撤稿／更正狀態。
- 新資料集先核對授權、標籤、感測器位置、採樣率及受試者切分；不直接假設可以訓練或部署。

本次來源蒐集有英文、MED 與搜尋排序偏差，並非完整領域清單。沒有排程自動下載、外部追蹤或全文再散布；需要定期更新時，可另行設定有明確範圍的維護工作。

`check_search.js` 需要 Node.js 18+，用最小 DOM 模型檢查產生 HTML 的搜尋與篩選邏輯。它不代替瀏覽器的畫面、鍵盤及輔助科技驗收。
