# 2026-07-11 變更日誌 — 達標判定穩定化(遲滯 + 寬限 + EMA 平滑)

> **相關文件**:[[HOME|導覽首頁]] · [[log_20260705_guided_redesign|前置:引導式重構]]

## 🎯 目的

使用者回饋「設定姿勢後判斷達標的邏輯不穩定」。訊號鏈審查確認三個根源:

1. **引擎無遲滯/寬限**:`inZone` 逐筆判定,單筆雜訊樣本跳出區間就清空保持進度、
   LED 熄滅、phase 退回 idle;值在邊界附近時瘋狂進出(flapping)。
2. **韌體互補濾波 `FILTER_ALPHA=0.85` 偏低**(一般 0.96–0.98):加速度計權重 15%/筆,
   時間常數僅 ~0.11s,肢體移動時線性加速度污染幾乎直通輸出——動作中最抖。
3. **App 端零平滑**:校準後直接餵引擎與畫面,大字帶 0.1 位每 40ms 跳動。

本次先修 App 端(1)(3);韌體 α 調整留待下次重燒(本來就有一次待重燒)。

## 🔧 變更內容

1. **TriggerEngine v3.1 穩定化**(`triggerEngine.ts`):
   - **遲滯**:進區維持嚴格區間;保持中判定區間向外放寬 `HYSTERESIS_DEG = 4°`
     (value 上下界與 segment 類膝直前置都放寬),邊界漂移不再進出抖動。
   - **出區寬限**:跳出放寬區間後啟動 `EXIT_GRACE_MS = 250ms` 計時,期間**進度凍結**
     (不發事件、不清零),回區即以原起點續算;逾時才 exit + 進度歸零。
   - rep 只會在「區內樣本」上完成,不會在寬限期間(區外)觸發。
   - 常數集中於 `movementMetric.ts`(與 REST_TOLERANCE 等同處)。
2. **EMA 平滑層**(新增 `services/smoothing.ts`,接線於 `bluetooth.ts`):
   - `AngleSmoother`:α=0.3,25Hz 下時間常數 ~0.12s;平滑基礎肢段角
     (thigh/shin/兩 roll),**knee/kneeRoll 由平滑值重算**保持恆等式;raw* 透傳
     (校準精靈 stdDev 驗證依賴原始值)。
   - 判定與顯示吃同一份平滑值(store 與引擎來源一致,量表上的值=判定用的值不變)。
   - reset 時機:硬體錯誤進入時、GATT 斷線時——復原後首筆重新播種,防舊狀態拖出假角度。
3. **顯示去抖**:MetricGauge 大字 `toFixed(1)` → `toFixed(0)`(0.1 位只傳達「不穩」)。

## 🧠 關鍵決策

- **寬限期間凍結而非續發進度**:若寬限中仍計進度,rep 可能在區外樣本上完成(體感怪、
  資料不誠實);凍結後回區補算,誤差上限即寬限長度 250ms,可接受。
- **DB 緩衝改存平滑後值**(隨 onAnglesReceived 傳遞):歷史資料=引擎實際判定所見,
  利於日後回放調參(遲滯/寬限參數可離線重播驗證)。
- **遲滯 4° < OVER_EXTENSION_MARGIN 10°**:放寬上界 (target+tol+4) 仍低於警報線
  (target+tol+10),保持中不會與超限警報重疊。
- 舊測試「單筆出區即歸零」為**刻意移除的行為**,測試檔已改寫為新規格
  (不再是 v2 迴歸鎖)。
