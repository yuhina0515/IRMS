# 2026-08-05 排錯日誌 — ESP32 插入電腦後序列埠未偵測到裝置

> **相關文件**:[[HOME|導覽首頁]] · [[README|系統規格 README]] ·
> [[AI_CODING_RULES|AI 協同開發規範]]

## 🎯 目的

使用者在準備燒錄韌體(對應
[issue #2](https://github.com/yuhina0515/IRMS/issues/2) 的第一步)時,回報 ESP32
插上電腦後,Arduino IDE / 系統的序列埠清單完全沒有列出裝置——這與
`doc/AI_CODING_RULES.md` 已記錄的「埠被佔用」(`Could not open COMx, the port is
busy or doesn't exist`,序列監視器開著或有背景程式佔用埠)是不同情境:那個情境
埠仍會列出來只是打不開,這次是**埠清單裡完全沒有這個裝置**,問題出在偵測不到
硬體本身,而非燒錄軟體衝突。

本專案文件先前只涵蓋「埠被佔用」,沒有涵蓋「埠完全不出現」的排錯路徑,故本次
補上。

## 🔧 變更內容

- `doc/README.md` §5.1 新增「5.1.1 排錯:插入電腦後序列埠清單沒有出現 ESP32」子節,
  依可能性排序列出四類原因與檢查步驟:
  1. USB 線材為純充電線(最常見)——無資料腳,電腦端完全偵測不到裝置。
  2. USB-to-Serial 驅動未安裝——ESP32 開發板上另有一顆 CP2102/CP2104(Silicon
     Labs)或 CH340/CH9102(WCH)橋接晶片,需個別驅動;附 Windows(裝置管理員
     未知裝置判讀)/ macOS(系統簽署驅動與隱私權封鎖)/ Linux(`dmesg`、
     `dialout` 群組、`brltty` 搶佔已知問題)三平台對應檢查方式。
  3. USB 埠/集線器供電或資料能力不足。
  4. 開發板本身未通電(板上電源燈判讀)、或 USB 轉序列晶片本身故障(需替換板子
     排除)。
