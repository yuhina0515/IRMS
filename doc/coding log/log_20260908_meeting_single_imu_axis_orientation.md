# 2026-09-08 會議紀錄 — 單顆 IMU 獨立判定軸向方向(axisSwap)設計方案

> **相關文件**:[[HOME|導覽首頁]] · [[README#2.1 六軸方向定義|六軸方向定義 README §2.1]] ·
> [[log_20260831_meeting_face_a_calibration_feasibility|前例:A 面校正可行性評估(否決)]]

## 問題

使用者今天在學校用真實裝置、**穿戴在真人腿上**做正常抬腿動作實測:內外翻正負號與文件
(`KR = shinRoll − thighRoll`,正 = 外翻)一致;但**小腿感測器的 roll 讀值會隨「向前抬腿
/ 向後抬腿」這個矢狀面動作變號**,照設計 roll 應只反應冠狀面動作,不該被矢狀面動作影響。
最可能的解釋:小腿感測器貼裝角度落在「正貼」與「貼歪 90°」之間,造成 pitch/roll 交叉耦合,
而現行 `detectAxisSwap()`(`calibration.ts`)是**二元**判定(`dRoll > dPitch` → 對調),
抓不到部分耦合的中間態。

決策問題:**設計一套讓單顆 IMU(只處理大腿或小腿其中一顆)能獨立判定自己軸向方向的方案**,
脫離現行綁在「兩感測器成對、配合六步精靈固定動作」的架構,並回答:判定方式(在體/離體、
量測序列)、能否從二元升級成量化角度、要不要整合進精靈、資料模型 migration 怎麼設計、
要不要先桌前純數學驗證再排真機時間窗。

## 與會者與立場

- **A(務實/漸進派)**:在既有六步精靈的**同一組動作**(前抬大腿/後勾小腿)上,把
  `detectAxisSwap()` 的二元位移量比大小,升級成對**已算出的 pitch/roll 角度輸出**做
  `θ = atan2(Δroll, Δpitch)`;抽成獨立可單獨呼叫的 `recalibrateAxis(limb)`,不必連
  另一顆感測器;`axisSwap:boolean` → `axisRotationDeg:number`,舊資料 `false→0`/`true→90`
  直接遷移;桌前合成資料驗證(含 0°/35°/90° 三個角度)。
- **B(嚴謹/風險分析派)**:同意升級成連續角度,但主張在**原始加速度向量 `(ax,ay)`**
  旋轉 `−φ` 後才算 `atan2`(而非對已算出的角度輸出做運算),並要求一個**第二個、近似
  正交的確認動作**當擬合優度守門(角度輸出運算只在中性姿態附近近似正確,大幅動作會失真);
  另要求 schema 版本標記、跨版本比對硬擋、量角器治具離體驗證算法本身。
- **C(操作/病患角度派)**:反對任何需要新器材、新真機時段的方案——這專案真機時間是
  最稀缺資源(裝置常常突然要還、測試常被迫中斷是這個 repo 自己的歷史)、且沒有量角器/
  治具、常常只有使用者一人身兼病患與操作者。主張把既有兩點擷取(站直基準+動作終點)
  升級成**連續掃描擷取全程軌跡**,用回歸擬合出耦合角度,不加任何新操作步驟、折進現有
  精靈步驟 2/3,不做獨立工具(視獨立工具等同於新排一次真機時段)。

## 交叉詰問

**攻擊 A(角度輸出 atan2)**:B 用實際數學推導證明這是**硬性退化**,不只是精度問題——
以真實旋轉角 φ=35° 為例,動作幅度 α=10° 時回推誤差僅 +0.11°,但 α=70°(精靈實際要求的
「前抬大腿」典型幅度)誤差已達 +6.1°,**α=90°(小腿後勾常見的膝屈曲幅度)時公式必然退化成
恆定 45°,不論真實 φ 是多少**——因為 `atan2(cosφ, 0)` 與 `atan2(sinφ, 0)` 在 φ 落在
0°–90° 之間時皆為 90°,資訊全部遺失。這正好是精靈刻意設計成大幅度、訊噪比佳的動作區間,
跟公式有效區間互斥。更致命的是:A 自己提出的驗證測試(0°/35°/90° 三點)**結構性抓不到這個
bug**——0° 與 90° 兩個邊界因為 `sinφ`/`cosφ` 其中一項恰為零而對此退化完全免疫,35° 若沒有
同時掃過幅度也不會觸發。B 也指出 A 主張的「不需要新裝置時間」與 A 自己承認的弱點(可能需要
第二個獨立動作處理 3D 複合傾斜)自相矛盾。**A 對此提出的角度輸出算法本身被判定不可用。**

**攻擊 B(原始向量旋轉 + 正交確認動作)**:C 承認 B 的核心數學確實更正確(旋轉原始向量能
避開角度輸出的非線性複合失真),但指出其**要求的正交確認動作,對小腿在解剖上不可行**——
髖關節是球窩關節,外展(冠狀面)是既有精靈第 4 步就在用的真實可控動作;但膝關節
(脛股關節)幾乎只有矢狀面自主活動度,冠狀面內外翻只是被動韌帶鬆弛的幾度,不是病患能
自主重現的可控動作,脛骨旋轉(另一候選自由度)幾乎不改變重力向量、加上本專案沒有磁力計
根本量不到。結果是:這個守門機制對小腿(恰好是今天真正出問題的那顆)**要嘛從不觸發、
形同虛設卻讓 UI 誤以為有驗證,要嘛卡死小腿校準永遠無法完成**。另外量角器治具離體驗證
牴觸專案「零器材、零外部量測」的實際工具箱,跨 schema 版本比對硬擋是超出這個 codebase
維護量能的開放式承諾(沒有資料存取層可以強制檢查,未來新功能很容易忘記擋)。

**攻擊 C(連續掃描擬合)**:A 指出「不加新操作步驟」只是把複雜度藏進擬合演算法本身——
回歸方法要選 total least squares 而非一般最小平方(否則 pitch/roll 誰當自變數會得到不同
偏誤答案)、正負號要靠取樣時間順序額外判斷而非幾何本身、且掃描全程無法像兩點法一樣只在
靜止時取樣,加減速過程的線性加速度污染會直接混進擬合輸入。更根本的問題:C 自己承認的弱點
(操作者非純矢狀面動作、退化構型)**沒有任何外部量測工具可以驗證**——重覆執行同一個
帶偏誤動作只會穩定收斂到同一個「自洽但錯誤」的角度,通過『重跑兩次結果一樣』這種唯一
可用的自我一致性檢查,卻是確信地錯。這比兩點法的雜訊(至少無偏)更危險。C 拒絕獨立工具的
理由(「等同於新排真機時段」)也被指出是稻草人——獨立工具可以是**同一次連線 session
內**的選單選項,呼叫跟精靈同一套單肢段擷取程式碼,零新裝置時間;維持現行單一線性精靈的
代價,是今天真正發生的情境會被重演:只有小腿有問題,卻仍要重新走過大腿站直/前抬,且
精靈完成時若一併寫回兩肢段校準,一次帶著污染的大腿重擷取可能**靜默覆蓋掉今天已確認正確
的大腿資料**——這個風險 C 完全沒有處理。

## 裁決

**核心數學採 B、獨立工具架構採 A、C 的連續掃描機制不採用。**

1. **軸向解算方式**:在**原始加速度分量 `(ax, ay)` 上旋轉 `−φ` 後再算 `atan2`**(B 的
   核心機制),用既有精靈同一個單一參考動作(大腿:前抬;小腿:後勾)的站直基準+動作終點
   兩點擷取即可解出 φ——不需要連續掃描,不需要新增操作步驟。A 的「角度輸出上直接
   `atan2(Δroll,Δpitch)`」已被證明在大幅度動作下數學退化,**不採用**。
2. **獨立單顆工具**:把單肢段的 φ 解算+校正邏輯抽成獨立可單獨呼叫的函式(如
   `recalibrateAxis(limb: 'thigh' | 'shin')`),不強制連著另一顆感測器,也不強制走完整
   六步精靈——同一次連線 session 內以選單方式暴露,精靈本身仍可呼叫同一份邏輯完成正常
   校準流程。這直接對應到今天的真實情境(只有小腿可疑,大腿已獨立確認正確),避免重演
   「修一顆順便動了另一顆好資料」的既有事故模式(2026-08-22 校準凍結快照的教訓)。
3. **資料模型 migration**:`axisSwap: boolean` → 數值欄位(如 `axisRotationDeg: number`),
   `false→0`/`true→90` 是精確映射,但**這不是真的「升級」**——舊資料從未記錄推導 φ 所需
   的原始通道,舊 session 應明確標記為 `legacy/unverified`,不能讓它看起來跟新流程量出來的
   數值一樣可信。**enforcement 範圍降級**:先只做被動 metadata 記錄 + 標記,**不**做
   B 主張的「任何分析/匯出路徑一律硬擋」這種開放式承諾——先只在目前唯一真的比較校準資料的
   地方(History 分析 modal 的 `calibrationDrift` 漂移比對)接上這個旗標,擴大範圍留給
   之後真的新增比較功能時再做。
4. **捨棄**:B 主張的「強制第二個正交確認動作」守門機制——對小腿無解剖上可行的替代動作,
   會導致守門機制形同虛設或卡死小腿校準,**不採用**;量角器治具離體驗證——牴觸專案實際
   工具箱(零外部器材),**不採用**,列為未來若取得合適器材時的加分診斷手段,非必要條件。
   C 的連續掃描回歸擬合——複雜度與可驗證性都劣於兩點法,**不採用**。
5. **強制前提**:任何新公式都必須先用**合成資料**驗證,且驗證組必須**掃過動作幅度**
   (不能只測固定幅度下的 0°/35°/90° 三點——A 的失敗案例證明固定幅度測試會讓公式的
   退化 bug 完全通過驗證卻仍是錯的),通過後才排真機時間窗。

## 最強的存留疑慮(需要監控)

三方都指出、且無人提出解法的真實缺口:**小腿沒有解剖上可行的獨立驗證訊號**,能確認
「旋轉原始向量後再算 atan2」在小腿身上真的解出正確的單軸扭轉角,而非把混合軸誤差
壓縮成一個看似合理但仍殘留耦合的數字(尤其若貼裝誤差不是單純繞感測器法向量的扭轉,
而是連皮帶平面本身都有傾斜的複合誤差,單一 φ 無法完整表示)。目前想得到的唯一低成本
替代信號,是**同一次擷取內重覆同一個動作 2–3 次比較 φ 的一致性**——這只能抓隨機誤差,
抓不到操作者每次動作都帶著同一種系統性偏差(例如同一人習慣性的動作路徑)的情況,是
明顯弱於「真正獨立驗證」的權宜方案,**本次裁決刻意不假裝它已解決**,留給下次拿到真機
時間窗時,先用這個弱信號跑一次,同時觀察解出的 φ 是否落在物理上合理的範圍(例如遠超
±90° 或跟目視貼裝角度明顯不符時應該人工存疑),作為現階段唯一的過渡防線。
