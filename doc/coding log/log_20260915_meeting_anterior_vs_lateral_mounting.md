# 2026-09-15 會議紀錄 — 感測器貼裝於正面(非外側)是否為校正長期不準的根因

> **相關文件**:[[HOME|導覽首頁]] ·
> [[log_20260908_meeting_single_imu_axis_orientation|前例:單顆 IMU 獨立判定軸向(φ 模型設計)]] ·
> [[log_20260912_axis_rotation_calibration_redesign|前例:軸向旋轉校正實作(真機驗證被跳過)]] ·
> [[log_20260829_meeting_auto_calibration_feasibility|前例:否決全自動校正]]

## 問題

使用者今天發現校正長期不準,一開始懷疑是「佩戴方式跟最初校正時不一樣」,追問後確認關鍵
事實反轉了假設:感測器最初的貼裝設定就是在肢段**正面**(矢狀面前側,anterior),不是
`doc/README.md` §2.1 建議的**外側**(冠狀面側面,lateral),且這個貼法從第一天到今天
**從未改變過**。這不是「隨時間漂移」,而是可能從第一天就存在的系統性根因,且跟
2026-09-08 會議已發現的「小腿 roll 讀值隨矢狀面動作變號(貼裝角度介於正貼與貼歪90°
之間)」同屬一類問題。決策問題:根因是否真是貼裝面不符;該改物理貼法(改貼外側配合既有
幾何假設)還是改數學(相信已設計但未驗證的 `recalibrateAxis`)去配合既成的正面貼裝事實。

## 與會者與立場(第一輪,獨立)

- **A(務實派)**:主張維持正面貼裝、相信軟體修正——`recalibrateAxis`/`buildCalibrationPatch`
  已在 6 步精靈中接上、`axisSwap:boolean → axisRotationDeg:number` 已完成 migration,
  「硬的部分已經做完了」,改貼法反而要使用者放棄已用數月的肌肉記憶。
- **B(風險分析派)**:直接讀 `angleMath.ts` 與 `log_20260912` 反駁——旋轉模型明確只繞
  「感測器自身法向量(az)」單一自由度,對應『同一面上扭轉』,換整個貼裝面是兩個自由度
  (法向量本身指向改變);單一 φ 用單一資料點求解,數學上保證能解出一個自洽但不代表正確
  的數字——跟 8/14、8/28 兩次事故同一種失敗特徵。`log_20260912` 自己承認真機驗證被跳過、
  README §2.1 刻意未更新。主張改貼外側,讓現實配合文件既有的簡單幾何假設。
- **C(病患/照護者操作角度)**:主張維持正面貼裝——大腿近似圓柱體,「外側」是沒有骨性
  標記、沒有清楚邊界的模糊窄弧,左右腿還互為鏡像需要心智翻譯;「正面」(尤其小腿脛骨
  前緣)是解剖上最好自行盲摸定位的標記之一。精靈步驟1文案目前是純文字、零圖示,整個
  `CalibrationWizard.tsx` 搜尋不到任何圖片,這本身就是獨立於本次爭議的 UX 缺陷。

## 交叉詰問與讓步

**攻擊 A**:B 指出 `log_20260912`「尚未做的」段落明確寫「真機驗證:需要裝置,本次不做」,
且 README §2.1 是刻意留到驗證通過才改——作者自己都沒簽字認為這套數學在正面貼裝的真人
腿上可信;`angleMath.ts` 的單自由度模型結構性無法代表「換整個面」這種可能雙自由度誤差。
**A 完全讓步**,承認「已經做完了」是錯誤的概括性主張,並補充幾何推導:大腿/小腿圓柱體
的「繞軸向軸(ay)重新定位」跟「繞法向量(az)原地扭轉」是兩個不同、一般不平行的旋轉軸,
正面貼裝是前者,`recalibrateAxis` 只驗證過後者(合成掃描測試只測同面扭轉)。A 提出新的
**分肢段**立場:大腿靠髖關節(球窩關節)有真正可控的外展動作(精靈步驟5,目前選配可跳過)
當獨立交叉驗證訊號,應改為校正時強制做;小腿因膝關節(樞紐關節)沒有對應的冠狀面自主
可控動作,`log_20260908` 自己承認小腿「沒有解剖上可行的獨立驗證訊號」,此為結構性、永久
不可驗證,主張小腿應改貼外側把誤差收斂回已驗證的「同面扭轉」情況。

**攻擊 B**:C 指出「改貼外側」不是零風險選項——小腿外側(腓骨側)沒有對應脛骨前緣的骨性
標記,大腿外側是圓柱體上沒有邊界的模糊弧,且 README §2.1 自己要求精靈額外詢問「配戴哪一
側腿」才能解左右鏡像,證明連設計者自己都承認「外側」是需要心智翻譯的相對概念,不是能被
直覺穩定複誦的絕對目標。**B 部分讓步**:承認原本「改貼外側=消除歧義」的主張錯在假設
使用者能穩定命中外側;若外側本身難以穩定命中,『改貼法』換來的可能是「不穩定、逐次漂移
的外側偏誤」取代「穩定數月未變的正面偏誤」,而 `recalibrateAxis` 單一 φ 修正的前提正是
「每次安裝誤差固定不變」——不穩定的偏誤反而更難修。B 修正立場:不堅持全面改貼外側,改為
承認小腿的脛骨前緣論點成立,但維持原本的機制疑慮(9/8 會議的 pitch/roll 耦合根因仍未解釋
清楚,不論最終選哪個面,真機驗證閘門都不該被今天的發現解除)。

**攻擊 C**:B(的核心論點)與 A 的讓步一起回頭檢驗 C 的「維持正面+相信軟體」主張——
正面貼裝的驗證缺口(單自由度模型 vs 可能的雙自由度誤差、真機驗證被跳過)同樣適用於 C 的
立場。**C 讓步**,收回「recalibrateAxis 可以當主力」的結論,改為支持**第三選項**:不爭
「正面」或「外側」這兩個詞本身,而是用**照片/圖示釘死一個解剖上好找的具體點**(小腿用
脛骨前緣附近的前側/前外側點,不是教科書定義的純外側,也不是現行未定義邊界的「正面隨便
哪裡」),把主要修正從數學改成「釘死目標」,`recalibrateAxis` 降級為吸收殘留小角度誤差的
輔助機制與 unverified 標記,精靈步驟6的即時動作預覽人工確認重要性不能因此被稀釋。

## 裁決

**不強制改貼外側;三方最終在『用圖示釘死具體點,而非用文字定義面向』上收斂一致,但大腿
與小腿的驗證能力不同,裁決分肢段處理:**

1. **根因確認**:「正面貼裝」是真實根因之一,且性質上屬於 2026-09-08 會議已經預先標記、
   從未解決的缺口——`recalibrateAxis` 的單自由度(繞感測器法向量 `az`)模型,理論上無法
   完整代表「換整個貼裝面」這種可能伴隨皮帶平面本身傾斜的雙自由度誤差。這不是新發現的
   bug,是舊會議已預見、今天才對上號的同一個存留疑慮。
2. **拒絕「全面改貼外側」**:外側在小腿上沒有對應脛骨前緣的骨性標記,在大腿上是圓柱面
   上沒有邊界的模糊弧,且 README §2.1 自己都需要額外的左右鏡像心智翻譯。強迫改貼外側
   可能把「穩定數月、有固定偏誤方向」的正面貼裝,換成「使用者每次都憑感覺猜、逐次漂移」
   的外側貼裝——而 `recalibrateAxis` 的單 φ 修正前提正是安裝誤差必須固定,不穩定的目標
   反而更難修、更危險。
3. **精靈必須加貼裝位置圖示**(獨立、立即可做,不等真機驗證):`CalibrationWizard.tsx`
   步驟1/6目前是純文字「綁於大腿外側/小腿外側」,零圖片。改為用照片或線稿釘死一個具體
   可觸摸標記的貼裝點(小腿以脛骨前緣附近為準);這個 UX 缺陷獨立於「正面/外側」的爭議
   本身就該修。
4. **大腿**:利用既有但目前選配可跳過的精靈步驟5(外展)作為免費的獨立交叉驗證訊號——
   髖關節是球窩關節,外展是真正可控、可重現的冠狀面動作。**校正時應改為強制完成**,不
   再視為選配,用它驗證 `recalibrateAxis` 解出的 φ 是否與外展動作量出的結果一致。
5. **小腿**:不强行要求改貼外側。膝關節沒有對應的冠狀面自主可控動作,9/8 會議已證明小腿
   結構性、永久沒有獨立驗證訊號——軟體修正在小腿上**無法被驗證**,不該被當成主力防線。
   維持現有即時動作預覽(精靈步驟6)的人工確認作為唯一有實績的防線(曾抓到 2026-08-14、
   2026-08-28 兩次真實生產環境缺陷),其重要性在這次討論後**不得被稀釋**,步驟1文案
   「方向角度不必在意」的語氣也不應誘導使用者低估現況的不確定性。
6. **文件閘門維持不變**:`doc/README.md` §2.1 正式文字與 `axisRotationVerified`/
   `calibrationDrift` 的 unverified 標記,依 2026-09-12 會議已裁決的決定,維持「等真機
   驗證(2026-09-08 會議行動項第4項)通過後再回頭改」——今天的發現不足以推翻那個閘門,
   只是再次確認了它存在的理由。

## 最強的存留疑慮(需要監控)

風險分析師在讓步後明確標記:把小腿脛骨前緣的強地標論點直接套用到大腿上是較弱的類推——
大腿正面「寬、好看」但不像脛骨前緣一樣有明確骨性邊界,大腿精靈圖示該釘在哪個具體點,
目前只有類推,沒有實際工作階段資料驗證過重現性。下次拿到真機時間窗時,應在落實第4點
(大腿圖示+強制外展驗證)之前,先實際比對幾次大腿貼裝位置的工作階段資料,確認選定的
圖示標記點真的比現行「正面隨便哪裡」更穩定可重現,而不是假設脛骨前緣的論證可以直接套用。

## 同日實作(會議後,不等真機時間窗)

裁決第4點原文是「大腿步驟5(外展)由選配改為校正時強制完成」。實作前重讀
`CalibrationWizard.tsx` 步驟5現場的既有註解,發現會議沒看到的事實:這一步是全精靈**唯一
需要單腳站立**的動作,對平衡受限的復健患者最困難,當初選配正是刻意為了這個可及性考量——
而且步驟5的 roll invert 判定**完全不進入判定路徑**(達標、次數、超限警報都不讀它)。強制
使用者做這個步驟去交換一個目前只影響顯示的驗證訊號,跟「不強制改貼外側」背後同一條
理由(不該為了驗證訊號犧牲病患安全/可及性)互相矛盾,屬於裁決本身沒考慮到的衝突。

**修正實作為:維持步驟5選配,但當使用者真的做了外展,順手用既有資料算出一個非阻斷的
提示**——外展理應是純冠狀面動作,若 `recalibrateAxis` 解出的 φ 真的完整代表了貼裝誤差,
外展前後的有效 pitch 應該幾乎不變;殘留量若達到該側 roll 動作幅度的 40% 以上
(`COUPLING_RESIDUAL_RATIO_WARN`),代表單自由度的 φ 可能沒有完全代表實際貼裝誤差
(例如貼裝面本身換了),在精靈步驟6(人工預覽確認)額外顯示提示文字,**不擋套用、不要求
重做**。這達成了裁決想要的「給大腿一個可以交叉驗證 φ 的訊號」,但不需要犧牲現有的
平衡可及性設計。
